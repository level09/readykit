# Changelog

All notable ReadyKit changes are documented here.

## Unreleased

### Security

- Require a verified Google or GitHub email before an OAuth sign-in links to an existing account by email or creates a new one. An unverified provider address could previously sign in as the ReadyKit user with that email. Accounts already linked to the provider still sign in.
- Upgraded Mako, oauthlib (4.0), urllib3, virtualenv, and Werkzeug, and the documentation site's Vue and source-map-js, for published advisories.
- Pinned the Fly.io deploy action to a release commit instead of its `master` branch.

### Changed

- Upgraded to SQLAlchemy 2.1, which uses psycopg 3 for `postgresql://` URLs; `psycopg[binary]` replaces `psycopg2-binary`. Plain `postgresql://` and `postgres://` URLs keep working. Derived projects must change `postgresql+psycopg2://` URLs to `postgresql://`, replace `psycopg2` imports and exceptions with `psycopg`, and recheck any psycopg2-specific `connect_args`.
- Upgraded Flask-Security-Too to 5.9.1 and Stripe's Python library to 16.0, now the minimum versions. `nh3` replaces `bleach`, and login uses Flask-Security's default email mapper, which also validates the address.
- Browser journeys in `tests/e2e` (opt-in with `RUN_E2E=1`) cover hosted checkout, the billing portal, cancellation, a failed renewal and recovery on a Stripe test clock, and team member access against a Stripe sandbox.
- Test Python 3.14 in CI. Pre-commit hooks run the project's locked Ruff, now 0.17.

### Fixed

- Acknowledge billing events for customers not linked to a workspace instead of returning HTTP 500. Checkout already reconciles the plan when it links the customer, and other applications' customers on a shared Stripe or Chargebee account no longer fail delivery indefinitely.
- Link OAuth sign-ins to existing accounts case-insensitively, matching password login, instead of creating a duplicate user.
- Count workspace members without a deprecated SQLAlchemy subquery.

## v1.6.0 (2026-10-14)

### Added

- `flask stripe-setup` fills a reusable Pro price and the local `stripe listen` webhook secret from an `sk_test_` key.
- `./setup.sh --yes` runs without prompts and keeps a provisioned `DATABASE_URL` from the existing `.env`.

### Changed

- Enable Google and GitHub login when both OAuth credentials are set; `GOOGLE_AUTH_ENABLED` and `GITHUB_AUTH_ENABLED` are no longer read. Blank and sample placeholder credentials keep a provider off, so a fresh install passes `checks.py --config`. To turn off a configured provider, remove its credentials.
- Removed the unused `STRIPE_PUBLISHABLE_KEY` setting.
- Corrected billing route examples, model field sizes, Docker Compose startup, background task, and blueprint examples in the guides.
- Fall back to `DATABASE_URL` when `SQLALCHEMY_DATABASE_URI` is unset, accepting the `postgres://` scheme.

### Fixed

- Pass the webhook events that current Stripe CLI versions require to `stripe listen` in the billing and deployment guides.

## v1.5.1 (2026-09-26)

### Added

- Check configuration before app startup with `checks.py --config`; add `--billing` to check provider settings without contacting services.

### Security

- Stopped publishing the Postgres and Redis container ports to the host in Docker Compose.
- Removed the shared `verystrongpass` fallback for `DB_PASSWORD` and `REDIS_PASSWORD`; Compose now refuses to start when either is unset.
- Removed the duplicate plaintext `DB_PASSWORD` and `REDIS_PASSWORD` entries in `.env-sample` that overrode the values generated by `setup.sh`.
- Updated vendored Vue, Vuetify, and Axios browser assets.
- Removed obsolete Passlib, Flask-Script, and Setuptools compatibility packages.
- Updated Cryptography and the documentation dependency tree to patched versions.

Thanks to Ali Tanveer ([@alivirgo](https://github.com/alivirgo)) for privately
reporting the Docker Compose port and default password issues.

### Fixed

- Make billing webhook processing retry-safe and reconcile plans from current provider subscriptions.
- Return Stripe and Chargebee billing portal users to workspace settings instead of a missing page.
- Check the Docker Compose Celery worker through Redis instead of HTTP.
- Install Redis and Celery dependencies in the production Docker image.
- Reject unsupported Python versions during setup.
- Configure Redis sessions and local cookie security correctly during setup.
- Replace deprecated Flask-Security, Flask-Session, and Flask-Caching configuration.

### Changed

- Align authentication, team, deployment, and contributor guides with the current code and remove stale duplicated instructions.
- Use SQLite sessions for local setup by default; enable Redis and Celery with `./setup.sh --full` or Docker setup.
- Clarified workspace query scoping and added route tests for cross-workspace access and revoked membership.
- Removed `enferno.__version__`; `pyproject.toml` is the single source of truth.
- Applied `ruff format` to the four files that had drifted from it.
- Test Python 3.11, 3.12, and 3.13 in CI.
- Run Ruff, pytest, smoke checks, and a production container build in CI.
- Added contributor, security, issue, pull request, community, and roadmap guidance.
- Removed unused scaffold templates.
